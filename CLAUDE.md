# Content Factory — Инструкции для агентов

## Проект
Автоматизированный конвейер создания видео-контента.
Находит трендовые YouTube Shorts → переписывает сценарий → генерирует озвучку → создаёт видео с аватаром → публикует на YouTube, Instagram, TikTok.

## Стек
- **Backend:** Python 3.12 + FastAPI + SQLAlchemy + PostgreSQL
- **Frontend:** Next.js 14 + TypeScript + Tailwind CSS
- **Очередь:** PostgreSQL-based job queue (встроенная)
- **Контейнеры:** Docker + Docker Compose

## Правила для ВСЕХ агентов
- Код только на английском (переменные, функции, файлы, комменты)
- Весь UI и текст для пользователя — на русском
- Никаких комментариев в коде если и так понятно
- После каждого завершённого шага — коммит в git
- Husky блокирует коммит если есть ошибки — исправить и повторить
- Никогда не коммитить .env файлы

## Роли агентов

### PM агент (главный — это я)
**Когда активен:** когда пользователь описывает задачу простыми словами.
**Что делает:**
- Переводит слова пользователя в конкретное ТЗ
- Определяет какие файлы нужно создать/изменить
- Разбивает задачу на шаги для других агентов
- Следит чтобы архитектура оставалась чистой
- Не начинает кодить сам — делегирует

### Backend агент
**Когда активен:** задачи в папке `backend/`
**Правила:**
- FastAPI роуты — в `backend/app/api/`
- Бизнес-логика — в `backend/app/services/`
- Модели БД — в `backend/app/models/`
- Схемы (Pydantic) — в `backend/app/schemas/`
- Конфиг — в `backend/app/core/config.py`
- Каждый сервис покрыт тестами в `backend/tests/`
- Использовать async/await везде где можно
- Все внешние API вызовы через httpx (не requests)

### Frontend агент
**Когда активен:** задачи в папке `frontend/`
**Правила:**
- Страницы — в `frontend/app/`
- Компоненты — в `frontend/components/`
- API вызовы — через `frontend/lib/api.ts`
- Стили только через Tailwind, никаких inline styles
- TypeScript строгий режим — никаких `any`
- Весь текст на русском

### Code Review агент
**Когда активен:** после того как Backend или Frontend агент закончил работу.
**Что проверяет:**
- Логические ошибки и баги
- Архитектурные нарушения (бизнес-логика не в роутах)
- Безопасность (SQL инъекции, открытые ключи, незащищённые роуты)
- Дублирование кода
- Типизация (нет `any`, нет игнора ошибок)
- Тесты написаны и покрывают edge cases
**Формат:** выдаёт список конкретных проблем с указанием файла и строки.
**Правило:** если нашёл проблемы — возвращает на доработку, не коммитит.

### Test агент
**Когда активен:** после Code Review если проблем нет.
**Что делает:**
- Запускает `pytest` для backend
- Запускает `npm run test` для frontend
- Если тесты упали — возвращает к нужному агенту с описанием что сломалось
- Только после зелёных тестов передаёт Git агенту

### Git агент
**Когда активен:** после зелёных тестов.
**Правила:**
- Коммит только если Husky не заблокировал
- Формат коммита: `feat: описание` / `fix: описание` / `refactor: описание`
- Никогда не делать `--no-verify`
- Никогда не пушить в main напрямую — только через PR
- Ветки: `feat/название`, `fix/название`

## Pipeline контент-завода

```
Поиск YouTube (ниша + ключевые слова)
    ↓
Транскрипт (Supadata API)
    ↓
Переписка сценария (Claude API) → QC проверка
    ↓
Озвучка (ElevenLabs API)
    ↓
Видео с аватаром (HeyGen API)
    ↓
Монтаж + субтитры (Creatomate API)
    ↓
Согласование (пользователь в дашборде)
    ↓
Публикация (YouTube + Instagram + TikTok)
```

## Статусы видео
`pending_transcript` → `pending_script` → `pending_voice` → `pending_video`
→ `pending_edit` → `review` → `approved` → `publishing` → `done`

Ошибочные: `error_transcript`, `error_script`, `error_voice`, `error_video`, `error_edit`, `error_publish`
Отменено: `cancelled`

## Масштабирование (учитывать с самого начала)
- Все настройки через переменные окружения (.env)
- Мультитенантность: таблица `users`, у каждого видео есть `user_id`
- API ключи хранить в БД зашифрованными, не в коде
- Роуты API версионированы: `/api/v1/...`
